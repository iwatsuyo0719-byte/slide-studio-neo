# 要件定義 — SLIDE STUDIO NEO

- 版：v0.1（案）／状態：**ユーザー承認待ち**
- 画面案（実装前の確認用モック。TOP 1ページで状態が切り替わる v2）は [mockup/index.html](mockup/index.html)
- 決定の経緯は [DECISIONS.md](../DECISIONS.md)、初期要望は [INITIAL_REQUEST.md](INITIAL_REQUEST.md)、参考UIは `references/ui/`
- 段取りの正本は姉妹Project slide-studio（`C:\Dev\AI_Workspace\01_Projects\Active\slide-studio`）。このツールはその段取りを画面から動かす入れ物で、段取りの中身は変えない

## 1. Goal

slide-studio の段取り（依頼保存→質問→設計図→本番pptx／HTML→自己検査→Codexレビュー）を、チャットに依頼文を書かずに、選択式の画面から使えるようにする。素材を入れて選択肢を選び「作成する」を押せば、編集できるpptxか動くHTMLが手に入る。

## 2. Scope（作るもの）

| 項目 | 内容 |
|---|---|
| 形 | 自分のPCで起動するローカルWebアプリ（ブラウザで開く）。1人で使う前提 |
| 裏のAI | PCに入っている Claude Code CLI か Codex CLI を、ツールのサーバーが呼ぶ（4章） |
| 画面 | TOP 1ページだけ。入力 → 生成中 → 設計図の確認（詳細版のみ）→ 完了 を、ページを移らずに右の領域と右端のパネルで切り替える |
| 保存 | 依頼1件＝1フォルダ。依頼文・素材・設計図・成果物・ログを残し、一覧から開き直せる |
| 公開 | GitHubで公開できる形（6章） |

## 3. Non-Scope（やらないこと）

- インターネットに置くサービス化（他人のアカウントでAIを動かす、ログイン機能、課金）
- APIキーでAIを直接呼ぶ方式（CLIのログインを使う。将来の拡張として残す）
- 議事録の文書（Markdown／Word）の作成。会議の中身はスライド（「会議まとめ」）として扱う
- 音声・動画からの文字起こし
- Googleスライド出力、動画の書き出し
- slide-studio 側のファイルの書き換え（読むだけ）
- 型（A基本／Bマッキンゼー流）を利用者に選ばせること（slide-studio どおりAIが選ぶ）

## 4. 画面の選択項目と挙動

画面全体は Notion のように白地・細い罫線・装飾なし。

### TOP（入力画面）の配置：1画面に収め、縦スクロールを起こさない

- 対象の画面サイズ：1280×720 以上で縦スクロールなし（2026-11-08 ユーザー指示）。それより小さい画面だけスクロールを許す
- 配置（上から）：
  - 上の帯：ツール名／作るAIの札（例「Claude Code・opus・high」）／履歴・設定のボタン
  - 中段の左：選択項目（題名・読み手・出力形式・目的・レベル）
  - 中段の右：素材（貼り付け欄が残りの高さいっぱいに伸びる＋ファイル置き場）
  - 下段：配色パネル（横一列。画面の幅いっぱい）
  - 最下段：生成時間の目安と「作成する」ボタン
- 過去の依頼の一覧は常時表示せず、上の帯の「履歴」から右側に引き出す
- 選択のボタンは大きくする：高さ46px以上・文字15px以上で、各行の幅いっぱいに均等に並べる。目的は2×2の大きいカード（高さ54px程度、記号つき）。左の列は上下に余白が偏らないよう、高さいっぱいに配分する（2026-11-08 ユーザー指示）
- 各項目の見出しは大きく（16px太字）、選ぶ順の番号を丸数字で付ける：1 読み手 → 2 出力形式 → 3 目的 → 4 レベル → 5 素材 → 6 配色 → 7 作成する。題名は任意なので番号なし（2026-11-08 ユーザー指示）

| 項目 | 選択肢 | 既定 | 選んだ時の挙動（AIへの渡し方） |
|---|---|---|---|
| AI（作るAI） | 入力画面の上の小さな札「Claude Code・opus・high」。押すとその場で変えられる（下記「AIの選び方」） | 設定で決めた物（初期は Claude Code） | 下記「AIの選び方」 |
| 読み手 | 社内／社外 | 社内 | 依頼文の「読み手」に入れる。社外は敬体・出所の厳しさを上げる（slide-studio の社内・社外の扱い） |
| 目的（スライドの種類） | 提案／報告／会議まとめ／説明・研修 | 提案 | 依頼文の「目的」と骨組みの指示を種類ごとに変える（下表） |
| 出力形式 | pptx／html（両方も可） | pptx | 依頼文の「出力」に入れる。pptx＝静止版（編集できるpptx）、html＝動く版（HTML 1ファイル） |
| レベル | 簡易／詳細／AUTO | AUTO | 簡易＝設計図で止めず本番まで、自己検査だけ。詳細＝設計図で止めてOK待ち、自己検査＋レビュー＋1周の手直し。AUTO＝AIが読み手・種類・素材の量から簡易か詳細かを選び、選んだ版と理由を画面に1行出す（以後はその版の挙動） |
| 配色 | 配色パネル（下記） | 026 浅瀬アクア | 依頼文の「配色」に入れる |
| 素材 | 文字の貼り付け欄＋ファイル添付 | — | 依頼フォルダに保存し、AIに読ませる |
| 題名（任意） | 自由入力 | 素材から自動 | 依頼フォルダ名 `YYYY-MM-DD-題名` に使う |

### AIの選び方（作るAI・モデル・考える深さ）

- **設定で1回決める**：設定画面で「作るAI」（Claude Code／Codex）・モデル・考える深さを決める。入力画面には小さな札で表示するだけで、押すとその依頼だけ変えられる（2026-11-08 ユーザー判断 1A）
- **レビューはもう一方のAI**：詳細版のレビューは、作るAIでない方が自動で担当する。片方しか使えない時は同じAIがレビューし「別のAIのレビューは未実施」と結果に書く
- **品質の下限**（下限より下は選択肢に出さない。2026-11-08 ユーザー判断 2A）：

| | 作る | レビュー（詳細版） |
|---|---|---|
| Claude Code | モデル opus 以上（opus／fable）、考える深さ medium 以上 | 同じ |
| Codex | モデル sol 系（gpt-6.1-sol／gpt-5.6-sol）、考える深さ medium 以上 | sol 系、high 以上（slide-studio の手順どおり） |

- **考える深さはレベルで自動**：簡易版＝medium、詳細版＝high（AUTOは選ばれた版に従う）。変える時は下限より上だけ選べる
- 選べる段階：Claude Code＝medium・high・xhigh・max（`--effort`）／Codex＝medium・high・xhigh・max・ultra（`-c model_reasoning_effort=`）。モデルは Claude が `--model`、Codex が `-m`
- 下限とモデル候補は設定ファイルに書き、試作の結果で上げ下げできる。「opus 以上」「sol 系」が品質の線引きとして正しいかは未検証（sol を上位とみるのは一覧の並びからの推測）
- 実機確認（2026-11-08）：Claude Code 2.1.319 の `--help` に `--model`・`--effort`。codex-cli 0.167.0 で gpt-6.1-sol・gpt-5.6-sol を `model_reasoning_effort` 付きで、APIキーの環境変数を外し ChatGPT ログインで実行して応答を確認。Codex のモデル一覧と対応段階は `~/.codex/models_cache.json`

### 目的（スライドの種類）ごとの骨組み

| 種類 | AIへ渡す目的の一文 | 骨組み |
|---|---|---|
| 提案 | 読み手に決めてもらう | 結論→根拠→打ち手→お願い（決めてほしいこと） |
| 報告 | 結果・進捗を正しく伝える | 結果→要因→次の一手 |
| 会議まとめ | 会議で決まったことを共有し、宿題を動かす | 決定事項→宿題（誰が・いつまでに）→残った論点。素材は文字起こしを想定（slide-studio の A3 を使う） |
| 説明・研修 | 仕組み・手順をわかってもらう | 全体像→部分→まとめ |

- 素材に「決めてほしいこと」などがあれば、そちらを優先する（選択肢は既定の型）
- 骨組みはAIへの指示にだけ使い、画面には出さない（選択肢は種類名とアイコンだけ。2026-11-08 ユーザー指示）

### 配色パネル

- DraggableMarquee（ObsidianUI・MIT）の動き：横一列のカードが流れ、ドラッグでき、離すと慣性で流れて止まる。カーソルを合わせると止まる。左右キーでも動く。「動きを減らす」設定では普通の横スクロール
- カード：配色100選（slide-studio の `PALETTES_100.md`）の各組を、5色の帯＋番号＋名前で描く（画像は使わない）
- 並び：先頭に「おまかせ（AIが選ぶ）」、続いて100組、末尾に「ブランド色（HEX入力）」
- 系統タブ（やさしい・ナチュラル など4系統）で絞り込める
- 押すと選択状態（枠線）になり、パネルの下に選んだ5色を大きく表示する
- おまかせ＝素材から近い3組をAIが選び、設計図と一緒に見比べ用HTMLを出す（slide-studio の「言葉で頼まれた時」の挙動）。簡易版では3組の比較を作らず1組をAIが決める

### 作成するボタン

- DiscoverButton（ObsidianUI・MIT）の仕様：ピル型、左に丸い矢印、ホバー／フォーカスで左から暗い塗りが広がり矢印が右へ動く。文言は「作成する」
- 素材が空の時は押せない。押すと同じページのまま生成中の状態になる（ボタンは「止める」に変わる）
- ボタンの横に生成時間の目安を出す（例「目安 約6〜9分」）。選択（レベル・出力形式・AI・モデル・深さ）を変えると目安も変わる

### 状態の切り替え（TOP 1ページのまま。2026-11-08 ユーザー指示）

| 状態 | 中段の右（素材の場所） | 右端のパネル | 左の選択・配色 | 最下段 |
|---|---|---|---|---|
| 入力 | 素材の貼り付け欄＋ファイル置き場 | なし | 操作できる | 目安＋「作成する」 |
| 生成中 | 下記「生成中の表示」（メーターのカード） | なし | 薄くしてロック | 「止める」 |
| 質問（必要な時だけ） | メーターのカードの下に質問（A/B/C）。1回まで | なし | ロック | 「止める」 |
| 設計図の確認（詳細版） | メーターは100%で止め「あなたの確認待ち」 | **右端から設計図のパネルが出る**：見出しの縦読み・ページごとの型・数字台帳と残った質問（折りたたみ）・直し指示・「OKで本番へ」（OK後の目安つき）。×で畳むと右端のつまみが残り、押すと再び開く。おまかせ配色なら3組の比較もここで選ぶ | ロック | 「止める」 |
| 完了 | 成果物のプレビュー（HTMLは画面内、pptxはページ画像を作れた時）＋検査結果・改善案＋直し指示（1周） | なし | ロック（「新しく作る」で戻る） | ダウンロード・フォルダを開く・「新しく作る」 |

- 過去の依頼の一覧は、上の帯の「履歴」から右側に引き出す。新しい順に並び、開き直せる

### 生成中の表示（あとどのくらいで終わるか）

- 大きなメーター（0〜100%）が動き、「残り 約3分」「経過 2:13」「目安 6〜9分」を出す（2026-11-08 ユーザー指示）
- メーターの下に段階の列（保存→設計図→本番→検査→レビュー→手直し。版で変わる）。済んだ段階に印、いまの段階は動いて見える
- 進み方の計算：
  - 段階ごとに時間の重みを持ち、済んだ段階の分＋いまの段階の経過時間で進める
  - いまの段階が目安を超えても、終わるまでは段階の上限の手前で止める（100%は本当に終わった時だけ）。目安を超えたら「目安より長くかかっています」と出す
  - 段階の切り替わりは、依頼フォルダに決まったファイル（design.md、成果物、review.md など）ができたことで判定する
- 目安の出し方：過去の実績（AI・モデル・深さ・レベル・出力形式の組み合わせごとの中央値）。実績が3件に満たない組み合わせは、初期値の表を使う（初期値は仮。試作で測って直す）

| 初期値（仮） | 簡易版 | 詳細版 |
|---|---|---|
| pptx | 約4〜7分 | 設計図まで約3〜5分、OK後に約8〜14分 |
| html | 約5〜8分 | 設計図まで約3〜5分、OK後に約9〜15分 |

- 詳細版は設計図で止まるので、メーターは「設計図まで」と「本番」の2回に分けて出す。待っている間はメーターを止め、「あなたの確認待ち」と出す

## 5. AIの呼び出し方式

- ツールのサーバー（ローカル）が、依頼フォルダを作業場所にしてCLIを非対話で起動する
  - Claude Code：`claude -p "<指示>" --model <モデル>`（作業フォルダの読み書きだけを許す設定で起動）
  - Codex：`codex exec -m <モデル> "<指示>"`（作業フォルダ内の書き込みだけ許す sandbox）
- 指示の中身：slide-studio の段取りファイル（`prompts/ROUTER.md` から必要な物だけ）＋画面の選択から組み立てた依頼文5行（何を・読み手・目的・素材・出力）＋版・配色の行。段取りは slide-studio の取り決めを変えない
- 段階ごとに起動を分ける：①質問の要否と設計図 →（詳細版はOK待ち）→ ②本番と自己検査 → ③レビュー → ④手直し。各段階の結果はファイルで受け渡す
- レビュー（詳細版）は Codex で行う（slide-studio どおり）。Codexが無い時は、選んだAIでレビューし「Codexレビュー未実施」と結果に書く
- 段取りファイルの置き場所は設定で指す：既定は slide-studio のフォルダ。原文プロンプト（`prompts/_source/`）も同じく設定で指す
- 進行はCLIの出力を流して画面に出す。失敗・中断はログを残し、その段階からやり直せる
- **サブスク専用**：各CLIのサブスクのログイン（Claude Code＝claude.ai の Pro／Max、Codex＝ChatGPT の Plus／Pro）で動かす。APIキーの入力欄は作らず、CLIを起動する時に `ANTHROPIC_API_KEY`・`OPENAI_API_KEY` などAPIキーの環境変数を外す（従量課金に切り替わらないため）。自前でAIと通信する部品（SDK＋サブスクのログイン流用）は作らない
- 作成前に各CLIの有無とログイン状態を確かめ、画面に表示する（Codex は `codex login status` で「Logged in using ChatGPT」を確認済み。Claude Code のコマンドは実装時に確認）。使えないAIは選べず、ログイン手順を1行添える
- **利用上限に達した時**：その段階で止め、成果物を残したまま「もう一方のAIで続ける」ボタンを出す。自動では切り替えない
- 使う前提：利用者が各CLIを入れ、サブスクでログイン済みであること

## 8. 受け入れ条件

1. 起動コマンド1つでローカルWebアプリが開き、Notion風の入力画面が出る。1280×720 以上では縦スクロールが起きない
2. 設定で作るAI（Claude Code／Codex）・モデル・考える深さを選べ、入力画面の札で依頼ごとに変えられる。下限より下のモデル・段階は選択肢に出ない。入っていない／ログインしていないCLIは選べない。起動時にAPIキーの環境変数が外れている
3. 読み手・目的4種・出力形式・レベル3種・配色・素材を選んで「作成する」を押すと、依頼フォルダに依頼文（5行＋版・配色）と素材が保存される
4. 簡易版：止まらずに pptx か HTML まで作られ、結果画面でプレビューとダウンロードができる
5. 詳細版：設計図で止まり、OKで本番へ進む。直し指示を入れると設計図が直る。本番後にレビュー結果が表示される
6. AUTO：選ばれた版と理由が1行表示され、その版の挙動になる
7. 配色パネル：ドラッグで動き、慣性で流れ、ホバーで止まり、キーボードと「動きを減らす」設定でも選べる。おまかせ・100組・HEX入力が選べる
8. 作成するボタンが DiscoverButton の動き（ホバーで塗りと矢印）をする
9. 過去の依頼を一覧から開き直せる
10. repoに APIキー・個人の素材・成果物・未許諾の原文が入っていない（`git ls-files` で確認）
11. 同じ依頼をチャットで slide-studio に頼んだ時と、段取り（止まる所・検査・レビュー）が同じ
12. 生成中にメーター・残り時間・経過時間・目安が表示され、段階が進むとメーターが進む。100%は完了した時だけ。作成するボタンの横に目安が出る
13. 同じ依頼を2〜3通りのAI・モデル・深さの組み合わせで作り比べ、下限が妥当か確かめて設定に反映する
