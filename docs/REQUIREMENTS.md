# 要件定義 — SLIDE STUDIO NEO

- 版：v0.1（案）／状態：**ユーザー承認待ち**
- 決定の経緯は [DECISIONS.md](../DECISIONS.md)、初期要望は [INITIAL_REQUEST.md](INITIAL_REQUEST.md)、参考UIは `references/ui/`
- 段取りの正本は姉妹Project slide-studio（`C:\Dev\AI_Workspace\01_Projects\Active\slide-studio`）。このツールはその段取りを画面から動かす入れ物で、段取りの中身は変えない

## 1. Goal

slide-studio の段取り（依頼保存→質問→設計図→本番pptx／HTML→自己検査→Codexレビュー）を、チャットに依頼文を書かずに、選択式の画面から使えるようにする。素材を入れて選択肢を選び「作成する」を押せば、編集できるpptxか動くHTMLが手に入る。

## 2. Scope（作るもの）

| 項目 | 内容 |
|---|---|
| 形 | 自分のPCで起動するローカルWebアプリ（ブラウザで開く）。1人で使う前提 |
| 裏のAI | PCに入っている Claude Code CLI か Codex CLI を、ツールのサーバーが呼ぶ（4章） |
| 画面 | 入力画面（素材＋選択肢）→ 進行表示 → 設計図の確認（詳細版のみ）→ 結果（プレビュー・ダウンロード・直し指示） |
| 保存 | 依頼1件＝1フォルダ。依頼文・素材・設計図・成果物・ログを残し、一覧から開き直せる |
| 公開 | GitHubで公開できる形（6章） |

## 3. Non-Scope（やらないこと）

- インターネットに置くサービス化（他人のアカウントでAIを動かす、ログイン機能、課金）
- APIキーでAIを直接呼ぶ方式（CLIのログインを使う。将来の拡張として残す）
- 議事録の文書（Markdown／Word）の作成。会議の中身はスライド（「会議まとめ」）として扱う
- 音声・動画からの文字起こし
- Googleスライド出力、動画の書き出し
- slide-studio 側のファイルの書き換え（読むだけ）
- 型（A基本／Bマッキンゼー流）を利用者に選ばせること（slide-studio どおりAIが選ぶ）

## 4. 画面の選択項目と挙動

画面全体は Notion のように白地・細い罫線・余白多め・装飾なし。上から順に1列で並べる。

| 項目 | 選択肢 | 既定 | 選んだ時の挙動（AIへの渡し方） |
|---|---|---|---|
| AI | Claude Code／Codex | 前回の選択（初回は入っている方） | 呼ぶCLIを切り替える。入っていないCLIは押せない状態で「未インストール」と出す |
| AIモデル | AIごとの候補＋「CLIの既定」。Claude Code＝fable・opus・sonnet、Codex＝CLIで動作を確かめた候補 | CLIの既定 | Claude は `--model`、Codex は `-m` で渡す。候補は設定ファイルで足し引きできる。プランで使えないモデルはエラーをそのまま画面に出す |
| 考える深さ（エフォート） | Claude Code＝low・medium・high・xhigh・max／Codex＝low・medium・high 等 | medium | Claude は `--effort`、Codex は `-c model_reasoning_effort=` で渡す。両AIとも選べる（Claude Code 2.1.319 の `--help` で `--effort` を確認、2026-11-08） |
| 読み手 | 社内／社外 | 社内 | 依頼文の「読み手」に入れる。社外は敬体・出所の厳しさを上げる（slide-studio の社内・社外の扱い） |
| 目的（スライドの種類） | 提案／報告／会議まとめ／説明・研修 | 提案 | 依頼文の「目的」と骨組みの指示を種類ごとに変える（下表） |
| 出力形式 | pptx／html（両方も可） | pptx | 依頼文の「出力」に入れる。pptx＝静止版（編集できるpptx）、html＝動く版（HTML 1ファイル） |
| レベル | 簡易／詳細／AUTO | AUTO | 簡易＝設計図で止めず本番まで、自己検査だけ。詳細＝設計図で止めてOK待ち、自己検査＋レビュー＋1周の手直し。AUTO＝AIが読み手・種類・素材の量から簡易か詳細かを選び、選んだ版と理由を画面に1行出す（以後はその版の挙動） |
| 配色 | 配色パネル（下記） | 026 浅瀬アクア | 依頼文の「配色」に入れる |
| 素材 | 文字の貼り付け欄＋ファイル添付 | — | 依頼フォルダに保存し、AIに読ませる |
| 題名（任意） | 自由入力 | 素材から自動 | 依頼フォルダ名 `YYYY-MM-DD-題名` に使う |

### 目的（スライドの種類）ごとの骨組み

| 種類 | AIへ渡す目的の一文 | 骨組み |
|---|---|---|
| 提案 | 読み手に決めてもらう | 結論→根拠→打ち手→お願い（決めてほしいこと） |
| 報告 | 結果・進捗を正しく伝える | 結果→要因→次の一手 |
| 会議まとめ | 会議で決まったことを共有し、宿題を動かす | 決定事項→宿題（誰が・いつまでに）→残った論点。素材は文字起こしを想定（slide-studio の A3 を使う） |
| 説明・研修 | 仕組み・手順をわかってもらう | 全体像→部分→まとめ |

- 素材に「決めてほしいこと」などがあれば、そちらを優先する（選択肢は既定の型）
- 骨組みはAIへの指示にだけ使い、画面には出さない（選択肢は種類名とアイコンだけ。2026-11-08 ユーザー指示）

### 配色パネル

- DraggableMarquee（ObsidianUI・MIT）の動き：横一列のカードが流れ、ドラッグでき、離すと慣性で流れて止まる。カーソルを合わせると止まる。左右キーでも動く。「動きを減らす」設定では普通の横スクロール
- カード：配色100選（slide-studio の `PALETTES_100.md`）の各組を、5色の帯＋番号＋名前で描く（画像は使わない）
- 並び：先頭に「おまかせ（AIが選ぶ）」、続いて100組、末尾に「ブランド色（HEX入力）」
- 系統タブ（やさしい・ナチュラル など4系統）で絞り込める
- 押すと選択状態（枠線）になり、パネルの下に選んだ5色を大きく表示する
- おまかせ＝素材から近い3組をAIが選び、設計図と一緒に見比べ用HTMLを出す（slide-studio の「言葉で頼まれた時」の挙動）。簡易版では3組の比較を作らず1組をAIが決める

### 作成するボタン

- DiscoverButton（ObsidianUI・MIT）の仕様：ピル型、左に丸い矢印、ホバー／フォーカスで左から暗い塗りが広がり矢印が右へ動く。文言は「作成する」
- 素材が空の時は押せない。押すと進行表示へ移る

### 進行表示・設計図・結果

| 画面 | 内容 |
|---|---|
| 進行表示 | いまの段階（保存→質問→設計図→本番→検査→レビュー）と、AIの出力ログ（折りたたみ）。止めるボタン |
| 質問（必要な時だけ） | AIが目的・読み手を読めない時の質問を、選択式（A/B/C）で表示して答える。1回まで |
| 設計図の確認（詳細版） | 見出しの縦読み・数字台帳・ページごとの型・残った質問を表示。「OKで本番へ」か「直し指示」（自由入力）。おまかせ配色なら3組の比較もここで選ぶ |
| 結果 | HTMLは画面内プレビュー、pptxはページ画像のプレビュー（作れた時）とダウンロード。検査結果（未達の項目）と改善案。「直し指示」を1周送れる |
| 一覧 | 過去の依頼を新しい順に並べ、開き直せる |

## 5. AIの呼び出し方式

- ツールのサーバー（ローカル）が、依頼フォルダを作業場所にしてCLIを非対話で起動する
  - Claude Code：`claude -p "<指示>" --model <モデル>`（作業フォルダの読み書きだけを許す設定で起動）
  - Codex：`codex exec -m <モデル> "<指示>"`（作業フォルダ内の書き込みだけ許す sandbox）
- 指示の中身：slide-studio の段取りファイル（`prompts/ROUTER.md` から必要な物だけ）＋画面の選択から組み立てた依頼文5行（何を・読み手・目的・素材・出力）＋版・配色の行。段取りは slide-studio の取り決めを変えない
- 段階ごとに起動を分ける：①質問の要否と設計図 →（詳細版はOK待ち）→ ②本番と自己検査 → ③レビュー → ④手直し。各段階の結果はファイルで受け渡す
- レビュー（詳細版）は Codex で行う（slide-studio どおり）。Codexが無い時は、選んだAIでレビューし「Codexレビュー未実施」と結果に書く
- 段取りファイルの置き場所は設定で指す：既定は slide-studio のフォルダ。原文プロンプト（`prompts/_source/`）も同じく設定で指す
- 進行はCLIの出力を流して画面に出す。失敗・中断はログを残し、その段階からやり直せる
- **サブスク専用**：各CLIのサブスクのログイン（Claude Code＝claude.ai の Pro／Max、Codex＝ChatGPT の Plus／Pro）で動かす。APIキーの入力欄は作らず、CLIを起動する時に `ANTHROPIC_API_KEY`・`OPENAI_API_KEY` などAPIキーの環境変数を外す（従量課金に切り替わらないため）。自前でAIと通信する部品（SDK＋サブスクのログイン流用）は作らない
- 作成前に各CLIの有無とログイン状態を確かめ、画面に表示する（調べるコマンドは実装時に確認）。使えないAIは選べず、ログイン手順を1行添える
- **利用上限に達した時**：その段階で止め、成果物を残したまま「もう一方のAIで続ける」ボタンを出す。自動では切り替えない
- 使う前提：利用者が各CLIを入れ、サブスクでログイン済みであること

## 6. 公開時の注意

- APIキー・`.env`・個人の依頼フォルダ（素材・成果物）はrepoに入れない（作業フォルダは `.gitignore`）
- 参考UIは ObsidianUI のMITコード。使う時はMITの著作権表示をrepoに残す。見本画像（cdn-new.obsidianui.dev）は使わない
- うちた氏の原文プロンプト・配色100選：ユーザーは「そのまま使ってよい・公開も可」と判断（2026-11-08）。**ただし原文はうちた氏の著作物で、本人の許諾の記録はまだ無い。** 公開repoに同梱する前に許諾の記録を `docs/` に残す。記録が無いうちは、repoには入れず設定で手元のファイルを指す形で動かす（ツールはどちらでも動く作りにする）
- フォント：Noto Sans JP と Material Symbols（Google Fonts）を使う想定。**実装前にユーザーへ可否を確認する**
- README に、必要な物（Node.js、Claude Code CLI か Codex CLI、slide-studio の段取りファイル）と起動手順を書く

## 7. 技術の前提（案）

- Next.js＋TypeScript＋Tailwind CSS（参考UIが shadcn 形式のため）、配色パネルは GSAP
- pptx生成は slide-studio どおり python-pptx（AIが作業フォルダで実行）
- Windows で動くこと（このPC）。macOS は確認できる範囲で

## 8. 受け入れ条件

1. 起動コマンド1つでローカルWebアプリが開き、Notion風の1列の入力画面が出る
2. AI（Claude Code／Codex）・モデル・考える深さを選べ、入っていない／ログインしていないCLIは選べない。起動時にAPIキーの環境変数が外れている
3. 読み手・目的4種・出力形式・レベル3種・配色・素材を選んで「作成する」を押すと、依頼フォルダに依頼文（5行＋版・配色）と素材が保存される
4. 簡易版：止まらずに pptx か HTML まで作られ、結果画面でプレビューとダウンロードができる
5. 詳細版：設計図で止まり、OKで本番へ進む。直し指示を入れると設計図が直る。本番後にレビュー結果が表示される
6. AUTO：選ばれた版と理由が1行表示され、その版の挙動になる
7. 配色パネル：ドラッグで動き、慣性で流れ、ホバーで止まり、キーボードと「動きを減らす」設定でも選べる。おまかせ・100組・HEX入力が選べる
8. 作成するボタンが DiscoverButton の動き（ホバーで塗りと矢印）をする
9. 過去の依頼を一覧から開き直せる
10. repoに APIキー・個人の素材・成果物・未許諾の原文が入っていない（`git ls-files` で確認）
11. 同じ依頼をチャットで slide-studio に頼んだ時と、段取り（止まる所・検査・レビュー）が同じ
