# 打合せ記録から議事録を作る

目的が「議事録」のときに読む。スライドは作らず、議事録の文書を作る。core.md の描画・型・スライドの規則は使わない（数値と根拠の誠実さの考え方だけは共通）。

## 着手

- 未整形の文字起こしを受け取り、まず meeting.md の「記録から採るもの」に従って台帳を作り、続けて議事録、自己確認までを1回の作業で止まらずに仕上げる。
- 台帳は依頼フォルダの ledger.md に保存する。台帳は議事録の材料なので短く作る（下の「台帳の形」）。
- 質問で止めない。素材で確認できない点は、生成を止めずに本文へ「未確認」と書いて残す。
- 速さを優先する。規則に書いていない確認（ハッシュでの照合、検証用スクリプトの作成、別のAIの起動、作業報告の作成など）はしない。

## 台帳の形

- 表だけで作る。表は「決定（理由を含む）」「宿題（担当・内容・期限）」「数字」「論点（反対・懸念の発言を含む）」の4つに絞る。各行は1文以内。
- 決定には、なぜそう決まったか（理由・条件）を必ず残す。論点には、結論の出なかった論点と、反対・懸念・条件を付けた発言を必ず残す（議事録の経緯の材料になるため）。
- 数値には単位と時点を付ける。発言の引用は、決定の理由や反対・懸念に使う要の発言だけを、素材の文字のまま「」で写す（言い換えない）。
- 議事録に使わない事実（報告の細部・雑談・決定につながらない数字の羅列）は台帳に入れない。検証メモ・作業手順・自己監査の記録・素材の写しも書かない。
- 台帳の分量は素材の1割程度を目安にする（1時間の会議で約1,500〜2,000字）。

## 台帳の規則を議事録にも当てはめる

- 数値は発言された値を保持し、単位と時点を付ける。概数には「約」を添え、確認できない値は xx にする。
- 相手の発言は短い引用として「」で保持する。要約で別の言い方に置き換えない。
- 決定と宿題は分けて書く。
- 文脈で確定できる誤変換は直してよいが、数値を推測で訂正しない。
- 文字起こしと添付資料にない数値は作らず、xx として残す。
- 相槌・雑談・世間話は載せない。事例として挙がった第三者の企業名・人名は載せない。
- 名称・日付など数値以外の空きは［　］で示す。

## 議事録の構成（この順で、見出しもこの名前にする）

1. 冒頭情報：会議名（表題）、日時、場所または形式、参加者（所属・氏名）、記録者。分からない項目は［　］か「未確認」
2. 決定事項：決まったことを箇条で書く。一つの箇条に一つの決定。条件付きの決定は条件も書く
3. 宿題：表にする。列は「担当」「内容」「期限」。担当や期限が素材で分からなければ「未確認」と書く
4. 論点と経緯：決定に至った論点ごとに、出た意見と主な発言の流れを要約して残す（なぜそう決まったか）。発言者が分かる場合は名前を添え、要の発言は「」で引用する。結論の出なかった論点は「継続」と書く
5. 次回の確認事項：次回までに確かめること、次回の日時（分かれば）

## 経緯の残し方

- 議題ごとに「論点 → 決め手・懸念 → 結論」を1行で残す。議題を省いたり、複数の議題を1行にまとめたりしない。
- 発言の順番を並べ直して因果を作らない。素材にない理由を補わない。
- 相関や印象だけから原因と結果を断定しない。

## 未確認事項

- 素材で確かめられない点（出席者の所属、期限の日付、数値の時点など）は、該当箇所に「（未確認）」と付ける。
- 文末に「未確認事項」の箇条を置き、本文で未確認とした点を一覧にする。なければ「未確認事項：なし」と書く。

## 書き方

- 読み手が社内なら常体（である調）、社外なら敬体（です・ます調）にする。
- 一文を短くし、主語と述語をはっきりさせる。長いダッシュ（—、——）は使わない。
- 枚数は素材の長さに合わせて、最初からその枠で書く（あとの自動短縮に頼らない）。15〜30分程度の短い会議は A4 1〜2枚、1時間程度の会議は A4 3枚までを上限とする。枚数は基本的に増やさないが、質（数字・決定の理由・経緯）は落とさない。
- 枚数を増やさない書き方：表題（# 会議名）と「## 冒頭情報」（日時・形式・参加者・記録者）と構成5項目の見出しは必ず書く。決定事項は1件1行で、決定の理由・条件を同じ行に短く添える。数字（費用の比較・予算の根拠・実績値など、決定の理由になる数字）は省かず、表にまとめる。宿題は「担当・内容・期限」の表にする。論点と経緯は議題ごとに1行まで（論点 → 決め手・懸念 → 結論）とし、すべての議題について1行ずつ残す。次回の確認事項・未確認事項は1件1行。枠に入らない細部（決定につながらない雑談・報告の細部）は書かない。
- Markdown で書く。表題は # 、各章は ## 、宿題は Markdown の表にする。文字の大きさや色は書かない（PDF にする時の決まりで整える）。

## 保存と検査

- 議事録は依頼フォルダの minutes.md に保存する。PDF（minutes.pdf）はツールのサーバーが作るので、AIは作らない。
- 構成5項目の順・宿題の表・引用が素材の文字と一致するか・xx と（未確認）の数・分量（字数）は、ツールが機械で確かめる。AIは自分で測らない。
- 保存したら一度だけ読み返し、判断が要る点だけを確かめて check.md に3〜6行で書く：決定と宿題を取り違えていないか、経緯が素材にない理由を補っていないか、確認できない点に「未確認」が付いているか。直す所があればその場で minutes.md を直す。
