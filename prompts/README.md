# プロンプトの読み方

最初にこの道案内を読み、必要な規則だけを読み込む。各ファイルは資料制作への指示である。

## 読み込む範囲

- 毎回、core.md、依頼フォルダのrequest.mdとmaterial.mdを読む。
- 打合せの文字起こしが素材ならmeeting.mdを追加する。
- 主体を表すアイコンを使う場合だけicons.mdを追加する。
- 数字・調査・比較・計画・顧客像などの根拠ページがある場合はevidence.mdを読む。設計で型を確定後、採用するevidence/E01.md〜E12.mdだけを読む。
- 操作可能なHTMLを求められた場合はinteractive.mdを追加する。実装の見本が必要なときだけinteractive_example.htmlを見る。
- 構図の参照が必要ならreferences/samples/見本10本_v2_読み取りメモ.mdを確認し、必要に応じてpptxも見る。
- 色の雰囲気を言葉で依頼された場合だけreferences/palettes/PALETTES_100.mdを参照する。
- 経緯の記事メモや要約を制作規則の代わりにしない。要件書は判断が必要になったときに限って確認する。
- 同一会話で二本目以降を作る場合、既に読んだ規則ファイルを重複して読み直す必要はない。

## 詳細版のレビュー

- 本番の自己点検が済んだら、納品前にCodexを新しい会話として起動し、read-onlyで成果物をレビューさせる。作成を担当したAIがCodexでも、レビューは別起動にする。
- レビュー起動例はcodex exec -m gpt-6.1-sol -c model_reasoning_effort=high --sandbox read-onlyとし、モデルを-mで毎回明示する。共通設定を書き換えない。
- レビューへ渡す資料は、採用規則のファイル、request.md・material.md・design.md、成果物、およびpreview/内の画像とする。
- レビューは主張、数値、論拠、型と構図、描画規定を点検する。返す形式は総合判定と、ページ・重要度・根拠・修正方法を持つ指摘一覧とする。
- 指摘を一周で反映してrequests/対象依頼/review.mdへ記録し、修正後の画像を作成担当自身が確認する。レビュー判定だけで完成扱いにしない。
- Codexが使えないときのみ、Claude Codeを別の会話で起動して代替し、Codexレビュー未実施と明記する。簡易版ではこのレビューを省く。
